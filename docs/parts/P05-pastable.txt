# XE P5 — jobs and image cache

## New public files
- `include/xe/jobs.h`: priority worker pool and render-thread completion pump.
- `include/xe/images.h`: URL+size image handles, render-thread texture upload, fade, budgets and diagnostics.
- `src/jobs/jobs.c`: pthreads on POSIX/Android and Win32 threads on Windows.
- `src/images/images.c`: libcurl downloads, disk cache, stb_image/libwebp decode, box downscale, render-thread uploads and byte-budget GPU LRU.
- `tests/p5_test.c`: 60-image TMDB poster grid, D-pad scrolling, and cache telemetry.

## Dependencies / P6 integration assumption
The P6 `include/xe/net.h` was not supplied in the prompt, so this part uses libcurl directly in the image worker rather than inventing a net API. When P6's contract is available, replace the small download helper with that API without changing `xe/images.h`. The source expects `stb_image.h` in `third_party/` and the platform's libcurl and libwebp development libraries. No dependency source is bundled here.

Use only permissively licensed dependencies: libcurl (curl license), libwebp (BSD), and stb_image (public domain/MIT dual option). No GPL code is used.

## Threading / lifecycle
Call `xe_jobs_init()` once after platform setup. Call `xe_img_pump()` once per render frame on the GL context thread; it pumps worker completions and uploads no more than two decoded textures per call. Release every image handle when no longer needed. Call `xe_jobs_shutdown()` during application shutdown, before destroying platform state. `xe_img_set_budget()` defaults to 64 MiB GPU and 150 MiB disk.

## Build
The supplied CMake file is a complete root example for this P5 integration. Install CMake 3.22+, SDL2 on Windows, libcurl, libwebp, and place the upstream `stb_image.h` in `third_party/`. Then:

```sh
cmake -S . -B build -DXE_BUILD_P5_TEST=ON -DXE_BUILD_P1_TEST=OFF -DXE_BUILD_P3_TEST=OFF
cmake --build build --config Release
```

Run `build/Release/xe_win.exe` on Windows. Arrow up/down scroll the poster grid. This test requires network access to `image.tmdb.org`.

## Limitations
- TMDB URLs are supplied as already-sized image URLs by the caller; this layer does not parse TMDB or metahub URLs to rewrite size paths because doing so could corrupt arbitrary URLs.
- Disk pruning uses file access time for files with the private `xe-images-*.bin` prefix in the configured cache directory. Filesystems that disable access-time updates provide approximate rather than exact LRU ordering.
- Network downloads are capped at 64 MiB per image and have connection/overall timeouts. Images are not decoded on the render thread.
