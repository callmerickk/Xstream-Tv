XE P4 — TEXT ENGINE IMPLEMENTATION BUNDLE
========================================

This is a single pasteable text bundle, not a ZIP. Create the files using the FILE sections below.
P3 dependency: include/xe/render.h (its exact contents are repeated at the end of this file).
Dependencies: FreeType 2 and HarfBuzz (with hb-ft integration). On Android, build both as native dependencies and link them into xe. On Windows, use CMake package targets or imported targets supplied by your dependency manager. Do not copy dependency source into this project unless you intentionally vendor it and preserve its licences.

IMPORTANT IMPLEMENTATION NOTES
------------------------------
- Font shaping is done with HarfBuzz; glyph rasterization/metrics come from FreeType.
- Font fallback is selected per Unicode code point before shaping contiguous runs. For complex scripts, keep each script run together; fallback selection must not split a conjunct/cluster. This implementation uses a conservative per-codepoint fallback choice and is a good P4 base, but should be upgraded to cluster-aware fallback before production.
- The glyph atlas is RGBA8 because P3's xe_tex_create/xe_tex_update API accepts RGBA pixels. Glyph coverage is stored in the alpha channel.
- Atlas eviction is LRU. When full, the atlas is cleared and glyph records are invalidated (safe but can cause repacking churn); the cache does not evict individual packed rectangles because doing so safely requires a free-rectangle allocator.
- The renderer API does not expose a texture-subrect update or a dedicated glyph draw. This implementation uploads the atlas on glyph changes and uses xe_r_image for each glyph. Since every glyph uses the same texture, P3 batching should keep these in the same texture batch.
- Shaped-run cache is a small LRU keyed by font pointer, UTF-8 string, width, and max-lines. Cache entries hold wrapped glyph placements, not raw HarfBuzz buffers.
- Text coordinates use the renderer's pixel coordinate space. x,y is the top of the first line's font box. XeFont px is in pixels.

NOTE ABOUT P3 API LIMITATION
----------------------------
The exact P3 API has no tint parameter for xe_r_image. Therefore a renderer-only implementation cannot correctly draw arbitrary XeColor text from an alpha atlas using the public API as written. For correct coloured text, add one of these small P3.1 extensions:
1) Preferred: add xe_r_image_tint(const XeTexture*, XeRect, float radius, XeColor tint, int contain) to render.h and the renderer, multiplying the sampled glyph alpha by tint alpha and outputting premultiplied tint RGB; or
2) Use a dedicated xe_r_glyph(atlas, src_uv, dst, color) batch primitive.
The xe_text_draw function above deliberately documents this limitation rather than silently claiming coloured text works. The API requested in P4 remains unchanged; implement option 1 internally and call it from xe_text_draw for production.
